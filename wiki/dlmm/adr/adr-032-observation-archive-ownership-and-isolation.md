# [[adr-032-observation-archive-ownership-and-isolation|ADR-032]] — A Durable Observation Archive Is Its Own Domain, Owned by an Isolated Read-Only Recorder

- **Date:** 2026-09-25
- **Status:** Active
- **Context:** Four EV inputs in `src/decision/ev/evCalculator.ts` are labelled `UNRATIFIED` — `PLACEHOLDER_FEE_YIELD_PER_HORIZON = 0.001`, `PLACEHOLDER_SIGMA_1S_STDDEV = 1.4e-4`, `PLACEHOLDER_DLMM_CONCENTRATION_MULTIPLIER = 1.8` and `PLACEHOLDER_DEPLOY_LAMPORTS = 200_000`. None can be calibrated retrospectively: the observations required do not exist, and `realizedVol1m_t` is set `null` at `src/index.ts:405` and never computed, so σ always takes the placeholder. The 2026-09-25 soak made the cost of this measurable rather than theoretical — across five days the EV payload was bit-identical to full double precision (`net_ev: 8004.657381574198`) while the Deribit spot moved from ~112 to ~120 and the planned range went from 22 bins to 47. The reward term does not respond to the range it projects reward for, because every term is a function of an unmoved active bin, an unmoved wallet balance and zero pool inventory. Separately, `SolanaPoolStateSnapshot` in `src/types/protocol.ts` carries no fee field of any kind, so the existing pipeline cannot record the data a calibration would need. `system_index.md` §2 maps no domain to observation history: `state_store.md` §2 owns restart-recovery facts and excludes caches deliberately, and `observability_contract.md` §1 governs telemetry emitted by a running bot. Per the routing rule, a ticket mapping to no domain must stop and escalate rather than improvise a subsystem.
- **Decision:** Create a new domain, **Observation**, with implementation root `src/observation/`, and author `docs/architect/observation_archive.md` as its binding blueprint. The archive is a **sibling observer** — downstream of nothing in the trading pipeline and upstream of nothing — recorded by a **separate process** whose isolation is structural rather than conventional: no `SOLANA_SIGNER_SECRET_KEY` in its environment, no `src/execution/` import in its runtime graph, its own `OBSERVER_*` configuration keys so a mainnet observation target can never reach the trading binary through a shared variable, and a filesystem separate from the State domain's, because `state_store.md` §5's write-then-rename atomicity is defeated by the full partition an unbounded archive is most likely to cause. The trading process may read the archive **never**: a measured quantity reaches the gate only as a ratified constant in `strategy.config.ts`, introduced by a later ADR. The schema is four append-only NDJSON streams with `schema_version` per record, adopting the field-level proposal in `todo/research/DRAFT_TICKET_C_Fee_Observer_Schema_And_Run_Spec.md`; `fee_observation` exists as a nullable field from schema version 1, so populating it once a measurement route is chosen is not a migration. Fee counters are cumulative, never interval-only. `bin_count` is mandatory on every cost observation. The archive stores observations and statuses and **no estimator output**, with one explicit exception — `active_bin_price_quote_per_base`, admitted because it is a closed-form function of four fields stored in the same record under `ev_policy.md` §5a and is therefore independently re-derivable.
- **Consequences:** Recording can begin before the fee-measurement route is decided, which matters because observation quality is a function of wall-clock time and the route decision is not yet takeable. `state_store.md` §6's exclusive ownership of durable restart state is preserved rather than weakened, and the trading boot path gains no dependency on an analysis dataset. Because the recorder performs no execution traffic, `config_contract.md` §5's Dual-LAN requirement is out of scope for it, so the DHCP-lease and manual-alias durability gap that blocks promoting the trading binary does not block the recorder — sidestepped, not solved. Gap semantics inherited from `data_ingestion_flow.md` §4 make a recorder outage cost an interval rather than the dataset, and the coverage-ratio rule makes an unqualified yield figure unpublishable. The costs are real: a second deployable artifact to supervise, a paid mainnet RPC endpoint assumed for sustained polling, roughly 1 GB per 21-day run retained indefinitely until an ADR authorizes deletion, and a canonical price formula now stated in two places — `ev_policy.md` §5a and the recorder — until a later implementation ticket hoists the helper to a shared module. Nothing here ratifies an EV placeholder, chooses a fee-measurement route, or authorizes capital.
- **Alternatives rejected:** Extend `state_store.md` to cover the archive — its §3 boot rule would place a growing analysis dataset inside a recovery path that has no logical dependence on it, and its §5 snapshot-replacement durability model cannot express an unbounded append-only series; extend `observability_contract.md` — its §2 ties records to the `OrchestratorEvent` categories and its §4 ties the schema to replay parity, neither of which a calibration series needs, and it presupposes a running bot where the recorder's purpose is to observe a pool the bot is not trading; run the recorder as a mode of the trading binary — it would share the binary's configuration, including `DLMM_POOL_ADDRESS`, which is exactly the path by which a mainnet observation target reaches an execution arm whose only remaining backstop is one boolean; record an `estimator_shadow` at write time — it would require importing `src/decision/ev/`, inverting the declared flow and coupling an irreplaceable dataset to a module under active revision, when the same residual series is obtainable at analysis time from preserved inputs; record fee accrual as interval deltas — fees earned during any missed sample would be lost permanently and invisibly; calibrate against the configured Devnet pool — five transactions in six months, an active-bin price near 6,937,303 quote units per SOL against a real market near 120, and a 0.8% bin step that does not represent the intended deployment.
