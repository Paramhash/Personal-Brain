# [[adr-036-single-volume-host-and-archive-free-space-floor|ADR-036]] — The Production Host Is a Single-Volume Windows 11 Machine, and a Free-Space Floor Replaces Partition Isolation

- **Date:** 2026-09-26
- **Status:** Active
- **Supersedes in part:** `observation_archive.md` §3 rule 4, and the structural claim in §3 rule 6. [[adr-032-observation-archive-ownership-and-isolation|ADR-032]] is otherwise unchanged.
- **Context:** `observation_archive.md` §3 rule 4 states that the archive "must not share a partition with the State domain's durable files", because `state_store.md` §5 requires write-then-rename atomicity, "which a full partition defeats; an archive that grows unboundedly is exactly the thing that fills one". §3 rule 6 then rests on that arrangement, asserting that "a separate process with a separate partition and disjoint configuration achieves this structurally, which is why that shape is required rather than recommended". Both were written against an assumed deployment topology — a separate Intel NUC running a POSIX operating system, pulling only `/production/`, with the archive on its own partition — and `docs/operations/nuc_preflight.sh` check 2 enforced rule 4 as a hard FAIL. **That host does not exist.** Measured on 2026-09-26, the machine holding both roots is `DESKTOP-PQP9JPL`, Microsoft Windows 11 Home 10.0.26200 build 26200, 64 GB RAM, Node v22.12.0, npm 11.4.1, with **exactly one filesystem** — `C:`, 1862.0 GiB total, 1181.9 GiB free, 36.5% used — holding `C:\Code\Active\dlmm-hedge-bot\development` and `C:\Code\Active\dlmm-hedge-bot\production` as sibling directories. The dispatcher confirmed on 2026-09-26 that this is the permanent production host and that no NUC will be provisioned. Rule 4 is therefore not merely unmet; on this host it is unsatisfiable. Separately, the control that would substitute for it did not work: **F-016** established that the recorder's disk alarm was inert for the entire life of the code — `assessHealth` raised `DISK_ALARM` only when `diskUsedPct` was supplied, and the recorder's sole call site in `observerMain.ts` passed the threshold `diskAlarmPct` without the measurement, so the branch was unreachable. The 80% alarm existed only in the POSIX shell wrapper printed by `nuc_preflight.sh`'s remediation block, which does not exist on this host. The state at the time of this decision was therefore neither partition isolation nor a working software guard. Capacity was never the issue and is not one: §8's expected use is ~480 MB per 21 days at radius 250 against 1181.9 GiB free.
- **Decision:** **Amend §3 rule 4 to permit a single-volume host, and substitute a free-space floor enforced by the recorder.** The archive may share a filesystem with the State domain when, and only when, the recorder enforces an absolute free-space floor on the archive volume, below which it **halts the run** rather than appending. The floor is configured by a new key, `OBSERVER_ARCHIVE_MIN_FREE_BYTES`, defaulting to 1 GiB (`DEFAULT_ARCHIVE_MIN_FREE_BYTES`), and it is deliberately **separate from `OBSERVER_DISK_ALARM_PCT`**: the alarm is a percentage that tells an operator to act, the floor is an absolute byte count at which the recorder acts on its own, and on a 1862 GiB volume 80% used still leaves 372 GiB, so one threshold cannot serve both purposes. A floor of zero or less is a configuration error, not a way to disable the stop. **The response to a breach is a halt, not a skipped append.** §7 rule 2 requires every intended sample to produce a record and forbids a silently absent one; a recorder that stayed alive while refusing appends would manufacture precisely that gap. Rule 2 names the one legitimate form of absence — "Absence of a record means the recorder was not running, and `run_events` says so" — so the floor is checked once at the top of `ObservationRecorder.tick()` before any append, returns a `haltReason` through the mechanism already used for a pool-identity mismatch, and `observerMain` turns that into `recorder.stop(reason)`, which writes the `RUN_STOP` record that explains the gap to a later reader. Checking before the first append is what reserves the space that record and the close-time gzip need. **F-016 is closed structurally rather than by patch:** `diskUsedPct` and `diskAlarmPct` are now **mandatory** fields on `HealthInputs`, so a call site that supplies a threshold without a measurement is a compile error rather than a silently inert alarm, and both callers — `observerMain.ts` and `observerHealthMain.ts` — measure the archive volume. The single probe is `NdjsonArchiveWriter.volumeStats()`, backed by a `volumeStats` member on the injected `ArchiveFs` surface and implemented over `node:fs.statfsSync` in `nodeArchiveFs.ts`, using `bavail` rather than `bfree` because space reserved for privileged processes is not space this process can claim.
- **Consequences:** The multi-week observation run can proceed on the host that exists, without hardware. **The assurance is lower than what it replaces, and this is the substance of the decision rather than a caveat.** Partition isolation was a structural guarantee: it held regardless of whether any code was correct. A free-space floor is a control: it holds only while the probe, the comparison, the halt path and the configuration are all correct. §3 rule 6's claim that the required shape "achieves this structurally" is no longer true on this host, and is amended to that extent — failure locality between the recorder and the trading process is now partly conventional. The four tests added with this decision are therefore load-bearing, not incidental. Two further consequences follow. First, a disk halt now ends the observation run, so a breach costs the remainder of the window rather than an interval, which makes the 80% alarm firing *before* the floor is reached the difference between an operator intervention and a lost run — and that alarm is the mechanism F-016 showed was inert, so its correctness is now on the critical path. Second, `nuc_preflight.sh` check 2's shared-filesystem FAIL is wrong on this host and must be replaced: the Windows preflight reports the exemption by ADR number and instead fails when the compensating control is absent, because a single volume is now the accepted state while a missing floor is not. This ADR does not authorize starting the recorder, does not resolve the co-located-roots promotion boundary, does not relax §9 retention, and does not ratify any EV placeholder.
- **Alternatives rejected:** **Provision a second physical SSD** and keep rule 4 as written — the strongest option, and rejected by the dispatcher on 2026-09-26 as not worth the hardware given that expected use is ~480 MB per 21 days against 1181.9 GiB free; the rejection buys convenience at the cost of assurance, which is why that trade is recorded explicitly above rather than implied. **Do not run the recorder on this host** — preserves the blueprint intact, but since no other host is coming it abandons the multi-week run rather than deferring it, and the run is the only route to ratifying the four `UNRATIFIED` EV inputs [[adr-032-observation-archive-ownership-and-isolation|ADR-032]] exists to serve. **Refuse individual appends and keep the process alive** — the design this ticket originally specified, rejected on reading §7 rule 2: it produces records that are silently absent while `run_events` still says the recorder is running, which is the exact failure the gap semantics were written to prevent, and it would let σ later be computed across a disk-induced gap as though the samples were contiguous. **Enforce a hard archive byte cap instead of a volume floor** — a cap bounds the archive but not the volume, so any other writer on `C:` could still starve the State domain while the recorder believed itself compliant; the floor measures the quantity that actually matters. **Reuse `OBSERVER_DISK_ALARM_PCT` as the floor** — one threshold cannot be both an operator-facing percentage and a self-acting absolute stop, and on a 1862 GiB volume the percentage that is right for a warning leaves hundreds of gigabytes, far past the point where a stop is meaningful. **Measure the volume inside `ndjsonArchive`'s writer path directly from `node:fs`** — it would put `node:fs` into the writer's require graph, which `jest.config.js` and §3 rule 2's isolation proof both depend on staying out; the probe is injected through `ArchiveFs` for the same reason every other filesystem call in that module is.
